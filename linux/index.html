Linux · the reference platform

Linux, all the way in.

AllMyStuff is built and tested on Linux first. It now drives GNOME on Wayland through the desktop's own remote-desktop interface, keeps X11 fully working, maps drives as you with no root, and ships packages for x86_64 and arm64. Here's exactly what works where.

The rest of the app · on every Linux box

Desktop, server, or a board in a drawer.

Most of the app never needed a screen. It works on any Linux machine that runs AllMyStuff, desktop or not.

New · drives

Map drives as you. No root.

Map a folder from any fleet machine to a real mount point, and every app sees it as ordinary storage. It runs as your signed-in user over FUSE: no sudo, no /etc/fstab line, cleaned up safely even after a crash.

Packages

Every format, both chips.

.deb, .rpm and AppImage for x86_64 and arm64, built on glibc 2.35. The .deb pulls in rclone and fuse3 for drive mapping, and the one-liner does too on apt systems.

Always On

Up after every reboot.

allmystuff service install runs the node as a systemd service, so terminals, files and sites stay reachable across logouts and reboots.

Headless

Servers join too.

allmystuff serve is the same engine without the window: for the build box, the home server, the NAS in the closet. Install with --no-gui and it never pulls a desktop app.

AMSTerm

A shell from your own terminal.

amst den-tower opens a real shell on another fleet machine. No sshd, no keys, no open ports, and a friend can attach to the same session.

Fleetfiles

Your files have a home here.

A Linux machine with room to spare offers a small 1 GB budget to Fleetfiles automatically, always leaving plenty free. Change it or turn it off in Settings.

Unattended access · plainly

What "always reachable" means.

Always On keeps the machine reachable. It doesn't invent a desktop that isn't there. Both halves, straight:

It does

  • Reconnect to a logged-in, unlocked GNOME desktop without asking for screen-sharing permission each time.
  • Keep terminals, files and sites reachable through logouts and reboots.
  • Tell you the real reason when control can't start, and keep the screen streaming while it does.

It doesn't

  • Draw a login screen, or start a desktop before someone has logged in.
  • Get past GNOME's lock screen.
  • Sneak input in through X11 on a Wayland desktop that doesn't offer it.

Need the login screen, the BIOS, or a machine that won't boot? That's a job for hardware. A CEC KVM watches the video signal and presses the buttons, OS or not.

If you can see it but can't drive it

Five things to check.

  1. Someone is logged into the graphical desktop you mean to reach.
  2. It's GNOME on Wayland, or X11, if you need keyboard and mouse.
  3. The desktop is unlocked.
  4. AllMyStuff is running in that same user's session.
  5. On other Wayland desktops, the screen-pick prompt was approved there.

The remote console tells you whether input is unavailable or simply not permitted. A working terminal proves the machine and the route are fine; it doesn't prove the desktop is reachable. For a per-user Always On install, the service's status and recent logs are one command each:

check the servicesh
$ systemctl --user status allmystuff.service
$ journalctl --user -u allmystuff.service -b --no-pager -n 100
